# April's writing preferences

Carried over from the Claude memory file `/preferences.md`. The agent in Cursor
has no access to that memory, so it lives here instead. Keep this file current.

- No hyphenated compound modifiers in drafted copy.
- Concise, tight language.
- When revising a document, deliver a copy with the changes highlighted so she
  can see what changed.
- For CTI explainer documents: open with the risk and why we care, put required
  actions next, and hold technical detail until later sections. The audience is
  leadership first and engineers second, in one document.
- "Plain" means direct and unhedged, NOT simplified. Write security documents in
  the standard security reporting register: no analogies or metaphors. State
  risk in security terms, credential attack surface, pre authentication
  information disclosure, remote code execution in the authenticating
  principal's context, rather than a layperson's paraphrase. Naming services and
  ports in a leadership facing section is appropriate; scan output and banners
  are not.
